# NPC Life 自动精简版

版本：`3.0.0-beta.6`

目标环境：SillyTavern `1.17.0`

作者：木子 （使用了gpt6.1 sol做的）

当前主版本暂时用自动精简版替代五页控制台完整版，集中验证“正常聊天 → 后台短活动 → 下一轮正文参考”。这是测试版，不是完整的自主世界模拟。

## 安装和更新

酒馆的扩展安装地址保持不变：

```text
https://github.com/muzi9277/npc-life
```

已从该地址安装的用户，在酒馆扩展管理中更新 NPC Life，然后 `Ctrl+F5` 刷新。手动安装时，将以下三个运行文件放入 `public/scripts/extensions/third-party/npc-life/`：

```text
manifest.json
index.js
style.css
```

根目录不再加载完整版控制台、地图或副 API 服务。旧安装留下的其他 JS 文件没有被新入口引用，不会自行执行。无需删除用户设置或重新安装。

## 使用

1. 打开角色聊天，在扩展设置中开启 **NPC 自动生活**（默认关闭）。
2. 名字留空时使用当前角色卡名。如果世界卡名称不是人物，请在折叠的“高级设置”填写一个明确的 NPC 姓名。本版每次只处理这一个人物，暂不支持群聊。
3. 正常聊天。一条新的 AI 正文完成且酒馆空闲后，插件检查是否满足最短间隔；满足时使用当前主 API 请求一次后台短记录。默认最短间隔为 10 分钟，可在高级设置调整为 1–120 分钟。间隔未到的回复跳过，不会在计时到点后自行补发请求。
4. 成功结果显示在开关下面，并在下一次正文请求中作为连续性参考。不会改写已经生成的回复，不会把后台文字追加到主聊天。

没有角色卡世界书可检索、请求失败或疑似截断时会显示原因。本版不循环重试；下一条新正文才可能再次尝试。关闭开关立即清空本扩展注入，历史短记录保留。

## 实际行为和边界

- 通过 `generateRaw` 发送有限的近期正文（最多约6000字符）、检索设定（最多4000字符）和该人物最近三条短记录。独立请求不自动携带整段聊天，但明确选取的正文会发送给当前主 API 并产生费用。
- 提示模型在场时只补小动作，离场时才写别处活动；遵守已知位置、限制和用户明确创作。此判断依靠模型，没有确定性路线或世界状态引擎。
- 每聊天最多保存20条，最近三条按深度3注入。私下活动不等于玩家知情；主模型是否遵守注入仍取决于模型与预设。
- 正文编辑、删除或切换候选会使来源不匹配的短记录及其后继失效。日志的 `day` 固定为1，本版不计算剧情天数。
- 关闭、切聊天、开始新的前台生成时丢弃过期结果。已经发出的请求不保证能取消或免计费。非聊天补全仍使用宿主共享的临时预算机制。
- 不含五页控制台、地图、联系人管理、副 API、记忆增强读写、资源关系结算或完整目标链。旧版功能不应作为本版能力宣传。
- 不保证任意嵌入模板或其他扩展的请求修改完全隔离；不宣称旧版约20字截断根因已经查明。

## 输出预算

聊天补全使用本次请求独有标记识别 `CHAT_COMPLETION_SETTINGS_READY` 载荷，设置本次 `max_tokens` 或 `max_completion_tokens` 为1200，不通过 `responseLength` 改主预设。非聊天补全使用宿主 `responseLength:1200`。这是前端载荷控制，不保证供应商遵守，也不等于目标中文字数。疑似断句输出不注入，不自动续写或重复消费。

## 数据兼容和重复安装

- 自动版数据存 `extensionSettings['npc-life-auto']`，按角色卡和聊天隔离；完整版 `extensionSettings['npc-life']` 不读取、不覆盖，降回完整版后仍可使用原数据。
- 自动版0.1.x使用者继续使用同一个数据键；旧全局短文本不迁入聊天。旧全局姓名只迁到首次打开的聊天，不继承到其他角色卡。
- 本版清理旧完整版的两个提示键，避免当前页面遗留注入；不会清空旧存档。
- 不要同时开启旧完整版和自动版。若另装过 `npc-life-auto`，停用其扩展并刷新；更新版具备同页重复初始化保护，但不能约束未经更新的旧副本。
