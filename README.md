# NPC Life 角色生活

版本：`3.0.0-beta.2`
目标环境：SillyTavern `1.17.0`（ST1.17.0）  
作者：木子 （使用了gpt6.1 sol做的）

NPC Life 是一个无构建、原生 ESM + jQuery 的 SillyTavern 前端扩展。它保留旧原型的 NPC 模拟与约束核心，并提供五页手机式控制台。控制台只负责 UI 与剧情相关的数据操作，不把页面结构当成剧情规则。

## 安装

将扩展包放入 ST 扩展目录：

```text
public/scripts/extensions/third-party/npc-life/
```

目录应包含以下 6 个运行文件：

```text
index.js
style.css
console.js
console.css
services.js
manifest.json
```

其中 `index.js` 是运行入口；`services.js` 负责 API 分流、只读记忆、独立后台试聊和地图导入；以包内 `manifest.json` 的实际声明为准。安装或更新后在浏览器执行 `Ctrl+F5`，打开扩展设置，确认版本条诊断显示 `3.0.0-beta.2`。本项目无 npm 依赖、无打包步骤、无后端。

## 功能边界

- 五页手机式控制台只提供界面和数据入口，不自动替剧情做决定。
- NPC 模拟、在场判断、地点约束、日志生命周期沿用旧核心思路：系统提供约束，模型负责演绎；不修改角色卡、世界书或主聊天记录。
- 用户明确写入当前剧情的事实优先于角色卡初始设定。正文事实提取仍是保守的模型分析与关键词启发式，不能保证理解全部否定、引用或时态；愿望、假设与低置信结果留待审核。用户可以在高级工作台校准状态，不受后台模拟限制。
- 新正史事实保存字段级撤销补丁；检测到来源消息编辑/删除后只撤销仍由该事实持有的字段。后来的独立修改保留，冲突与旧版无补丁记录标记待复核，绝不整档恢复旧基线。高级工作台的“待审核正文事实 → 正史来源与撤销记录”可手动撤销投影。相关事实链存在依赖时需要人工校准，不宣称完整事件溯源重放。
- 联系人支持“删除”与“永久忽略”，两者均可在档案恢复。数据按角色卡世界隔离，重扫不会复活角色；生活事件、日记与试聊历史保留。涉及角色的行程组暂停，恢复角色不会自动续行。同行组事实保留，归档成员所在组停止自主模拟，需用户显式调整。
- 联系人页可查看 NPC 状态和日记。日记目标字数可选 `50`、`200`、`800`、`1600` 或“自定义”。目标是提示参数，不保证输出精确达到该字数。
- 联系人页的“试聊”是独立后台会话：结果不写入主聊天、不改变世界状态，只有用户主动按按钮才请求模型。
- 地图页只处理自身确认的地点、`tags` 与路线。导入地图 JSON 后，候选地点和路线必须由用户确认才进入自身目录；目录不写卡。
- 地图图片只接受本地 `PNG`、`JPG/JPEG`、`WebP` 数据 URL。不会自动兼容或调用第三方地图 API。

## 开始使用与界面

1. 打开 NPC Life → 动态 → 高级世界工作台，重扫当前卡，确认角色和地点；误识别人物可到联系人删除或忽略。
2. 点击“同步正文事实”，检查待审核条目，必要时校准当前位置与行动限制。
3. 离场角色可推进一天模拟；在场角色用“小动作”。联系人页选择有事件的日期，生成可读日记或独立试聊。
4. 设置页修改后点击保存，取消会还原未保存偏好。临时草稿在本次界面切换中保留，切卡/切聊天清除，刷新页面不保存未提交草稿。

控制台按窗口自身宽度切单双列，支持拖动、缩放、最小化、最大化和关闭。无地图底图或坐标时不预留空画布。空数据会给出下一步提示。

当前仍未实现自动按频率调度、人物别名合并、世界书地图自动适配或完整目标行动后果链。这是修复版测试发布，不将这些规划功能列为已完成。

## 地图 JSON

导入文件使用以下结构。`id`、`fromId`、`toId` 可省略；省略时可使用对应的名称字段匹配。坐标范围是 `0..100`，路线天数必须是整数。`image` 只能是本地图片数据 URL。

```json
{
  "locations": [
    {
      "id": "harbor-01",
      "name": "雾港旧灯塔",
      "tags": ["海边", "高处"],
      "x": 24,
      "y": 68
    },
    {
      "id": "market-01",
      "name": "铜铃集市",
      "tags": ["集市"],
      "x": 66,
      "y": 44
    }
  ],
  "routes": [
    {
      "fromId": "harbor-01",
      "toId": "market-01",
      "durationDays": 1
    }
  ]
}
```

`image` 为可选字段，格式限 `data:image/(png|jpeg|webp);base64,` 后跟完整 Base64 图片数据；[完整示例](examples/map.example.json) 附带真实微型 PNG。

导入只产生待确认候选；用户确认后才保存。候选失败、未知字段或无法确认的路线保持未知，不会自动猜测或写入地点目录。

## API 与连接

主 API 生成使用 `generateRaw`，默认使用 ST 当前选定配置。插件不会通过静默续写接口把主聊天记录带入生成。

ST 副 API 使用已核实的 `ConnectionManagerRequestService` 方法 `getSupportedProfiles` 与 `sendRequest`。先在酒馆连接管理器配置连接 profile，再在 NPC Life 设置中选择并保存副连接及各任务路由。连接详情窗口只展示实际可用的连接名称、模型与预设，不提供未实现的地址、密钥、温度或超时编辑器。`preset`、`model` 继承所选 profile；插件不切换主连接。副 API 失败不会静默回退主 API。“测试副连接”只走已保存所选副连接，独立使用 64 token 预算，不受分析任务路由影响。

最大生成 token 是模型响应预算，和文章目标字数不同。主 API 将预算交给 `generateRaw.responseLength`；原先约 20 汉字截断的根因尚未通过真实 Network 确认，不能保证预设或上游不会覆盖。副 API 将预算直接交给 `sendRequest` 第三参数；若输出仍短，请检查所选 profile 的输出/推理预算及服务商响应，插件不会偷偷换昂贵连接或自动多次续写。

模板只附加文本。插件不提供生成前 hard interception，也不能保证主模型遵守注入内容；解析到未知内容时保持未知。

## 记忆增强读取

可选读取 `window.stMemoryEnhancement.ext_getAllTables`（已核实版本 `2.2.19`）获取当前聊天最近的非用户消息表。读取默认关闭，开启后按关键词和行预算截取；相关行会发送给用户选定的 API。过期表格不会覆盖当前状态，也不会写入外部表。记忆读取是本地读取，但开启相关功能后仍可能产生模型请求。

## 数据与隐私

- 只有用户主动点击生成或试聊等模型操作按钮时才触发模型请求；地图导入确认等本地操作不因此请求模型。
- 插件不会自动跨消息调用模型，也不宣称“自动”或“不计费”。实际费用和请求行为取决于用户选择的连接配置。
- 持久化数据存放在 `extensionSettings['npc-life']`；界面布局和折叠状态使用浏览器 `localStorage`。
- 副 API 密钥由酒馆连接配置管理，插件自身不保存密钥。
- 连接功能目前限本机测试；本项目没有声称已调用真实 API 完成全部联调。
