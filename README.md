# NPC Life

当前推荐版本：`3.5.4`

仓库里还留着上一份酒馆助手脚本 `3.5.3`，以及根目录可单独安装的旧扩展 `3.3.10-sync`。

让在 SillyTavern 里玩的时候，剧情里的 NPC 可以自由活动。这还是完全的测试版本，有问题请告诉作者，由作者来改进。

## 介绍

`3.5.4` 是一份酒馆助手（JS-Slash-Runner）脚本，安装文件是 [`script/NPCLife-3.5.4.json`](script/NPCLife-3.5.4.json)。脚本显示名是 `NPC Life 3.5.4`，脚本 id 仍是 `923cea18-89d1-47c1-ac88-13555709f9dc`，运行版本字符串是 `3.5.4`。[`script/NPCLife-3.5.3.json`](script/NPCLife-3.5.3.json) 是已经发布过的上一份脚本，文件内容保持不动；两份 JSON 用的是同一个脚本 id，导入 3.5.4 会替换脚本库里的 3.5.3。

3.5.4 沿用 3.5.3 的融合构建。外壳使用 [彼方 · NPC 幕后生命状态系统](https://github.com/ninin99537-commits/BiFang)。彼方的发布账号是 `ninin99537-commits`，仓库首页与提交说明里的项目名写作「彼方 · NPC 幕后生命状态系统」，源码目录是 `彼方_NPC幕后生命状态系统`。彼方采用 [PolyForm Noncommercial License 1.0.0](https://polyformproject.org/licenses/noncommercial/1.0.0)（非商业许可）。NPC Life 在这层外壳上增加自己的世界层功能。面板、外壳，以及 NPC 状态的更新流程，仍以彼方为原项目；本仓库不是彼方的官方发布处。

`script/NPCLife-3.5.4.json` 和 `script/NPCLife-3.5.3.json` 里都含有彼方外壳代码，使用时须遵守上述非商业许可，条款见 <https://polyformproject.org/licenses/noncommercial/1.0.0>。本仓库根目录的 3.3.10-sync 扩展仍未附单独的 `LICENSE` 文件，原作者标记为 muzi。

这仍是完全的测试版本。使用中有问题，请告诉作者 muzi（GitHub：[muzi9277](https://github.com/muzi9277)），由作者来改进。

## 安装 3.5.4

先在 SillyTavern 里装好酒馆助手（JS-Slash-Runner）。

1. 取得本仓库中的 `script/NPCLife-3.5.4.json`。
2. 在酒馆助手的脚本库里导入这个 JSON 文件。
3. 确认脚本名称是 `NPC Life 3.5.4`，然后启用。
4. 刷新酒馆页面后再开始聊天。

3.5.4 只通过酒馆助手导入并启用。安装位置不是：

```text
public/scripts/extensions/third-party/npc-life/
```

那个目录留给下面的 3.3.10-sync 第三方扩展。不要用这份 JSON 替换仓库根目录的 `manifest.json`、`index.js` 等扩展文件。

## 3.5.4 怎么用

启用后，剧情里的 NPC 可以在幕后继续活动。面板和 NPC 状态更新沿用彼方原来的流程；下面这些是 NPC Life 加上的世界层。

- 日志页底部有「闭环自检」按钮，用来查看本轮 tick、计划是否被提升、队列是否到期、传闻与邻接、钩子缺席次数、注入字数。
- 玩家说「第二天」「过了三天」「一周后」「等了片刻」等时间词时，会按 1 拍、3 拍、7 拍、1 拍推进时间，连续结算后再生成正文。同一句里出现多处时间词时，取最长的那一档，不把拍数加在一起，最多 14 拍。说「第二天」会真正推进世界层。
- 每人有知情账本：在场是亲眼见到，听来的标成传闻，没记下的就是不知道。这份账本会注入给主模型。
- 「平行视角」折叠块用来写后台小剧场，和「背景状态」是分开的。标签仍是 `<npc_life_parallel>`。
- 已纳入官方彼方 2026-11-23 的烟火世界动向条件提示，并放宽了原先「不制造大剧情」的提示词限制，允许已有计划或依据的行动正常进展。
- 面板「NPC Life」里有「按角色隔离调用」，默认勾着。

### 按角色隔离

幕后状态、背景近况、平行视角，以及知情备注，不再共用一次看完全部角色的请求。脚本先做一次很短的预筛：候选名字加上最近 4 条公开对白，不附档案、活动总表、传闻、队列或整本知情账本。预筛失败时，改用本地判断：谁出现在这几句对白里，以及谁自己的档案里还有正在做的事。然后每个入选角色单独请求一次。这一次只放：

- 这个角色自己的档案字段
- 知情账本里已经记在这个角色名下的条目（亲眼或传闻，附上对应事件的摘要）
- 若对白里看得到这个角色，或位置和当前玩家所在一致，才附上那几句公开对白；人不在场就不附对白

不会放进这次请求的东西：其他角色的档案和私事、活动总表、传闻总表、队列、邻接，以及其他人的知情名单。请求发出前还会核对：别人的「心事 / 藏起来的打算」若不是这个角色已知或当场听见的，就取消这次请求。

世界层怎么结算、`ledger.knows` 怎么区分亲眼和传闻，都没有改。后来的传闻仍然不能覆盖已经亲眼记下的条目。模型如果在隔离结果里确认某件事，只能确认本来就在这个角色名单里的 eventId，不能给别人新增一条。

隔离调用会占发送前的一点时间。背景和平行视角整轮最长大约 22 秒；单个幕后更新大约 28 秒。超时或生成器不可用时，背景和平行视角退回 3.5.3 那种「写给主模型的提示词」，发送继续。幕后更新如果一个角色都没写成，且不是超时，才退回原来的合并请求，并在控制台写明这一轮退回了。超时则本轮不改卡，也不再补发合并请求。名册还是空的、又开着自动建档时，仍走原来的合并请求，方便第一次建档。不想要这些额外调用时，取消「按角色隔离调用」。

主模型没有被做成全隔离。世界层注入、整本知情账本，以及拼好的背景 / 平行视角块，仍会在之后一起交给主模型。隔离约束的是「替每个角色生成内容的那一次请求」，不是主聊天本身。

世界层只在玩家说出的时间跨度内结算。隔离成功时，背景和平行视角的文字来自各角色自己的请求，主模型只负责把拼好的标签原样放在回复末尾。隔离失败时，仍由主模型按旧提示自己写。

### 别名

更新角色卡时，模型会把正文里对这个人的昵称、头衔、简称写进「别名」。已有的「曾用名」会先种进这份名单。改名合并（例如 林姐 → 林淑仪）时，旧名留在别名里，之后正文再写 林姐 仍能对上这张卡。

名单会去掉空白、空项和重复，也不会把正式姓名再存成它自己的别名。只有一个字的称呼不收。没有别名的角色，匹配方式和 3.5.3 一样。

这些名字会一起参与原来的匹配：场景里是否提到、痕迹打分、背景状态对上折叠块、世界书条目，以及在场提示。英文仍按原来的词边界；中文正式姓名仍是原来的包含判断。别名多一条限制：如果它只是嵌在另一个更长的已登记名字里面（例如别名「玛丽」撞上正文里的「玛丽莲」），这次不算提到它。世界书键名仍用原来的双向包含，别名也可能因此命中更长的条目名。没有做编辑距离或模糊匹配。

## 旧版：3.3.10-sync 第三方扩展

仓库根目录的 `manifest.json`、`index.js`、`style.css` 等文件仍是 SillyTavern 第三方扩展 `3.3.10-sync`。源码保持原样，可以按原来的文件夹方式安装。它和 3.5.x 的 JSON 脚本是两种安装包。3.5.4 没有改这些根目录文件。

安装到：

```text
public/scripts/extensions/third-party/npc-life/
```

仓库地址：

```text
https://github.com/muzi9277/npc-life
```

对应发布：

<https://github.com/muzi9277/npc-life/releases/tag/v3.3.10-sync>

目标环境：SillyTavern `1.17.0`。更新后执行 `Ctrl+F5`。运行文件为 `manifest.json`、`index.js`、`style.css`、`console.js`、`console.css`、`services.js`、`automation.js`、`timeline.js`、`world-service.js`、`activity-ledger.js`、`living-world.js`、`background-status.js`。

这一版按角色卡隔离世界，记录已追踪 NPC 的活动资料与可发现痕迹，在正文结束后结算，下一轮按当前场景注入。地点只作软约束；异地偶遇是低概率的「可能路过」机会，不计算地图或路线。

### 这一版的能力

- NPC 活动资料库：保存做过、正在做、准备做的已提交活动。
- 痕迹延迟发现：确实会留下可观察物证的行动才生成痕迹；玩家后续调查或进入相关场景时才提供线索机会。
- 发现写回：只有玩家视角实际写出发现才记为已发现；NPC 自己发现、调查提问、路过和偶遇不会记成玩家已知。
- 每轮正文结束后结算；本轮新结果最早下一轮生效。正文没写经过时间按 0 分钟。
- 动态世界书、公开世界状态重合、低概率偶遇和地点软权重。
- 「背景状态」：追踪人物默认开启，可随时取消勾选。主模型按设定间隔（默认每 3 条角色回复）写出短近况，插件把它收成最新一条角色回复下默认折叠的块；不是生成轮次时沿用上次近况，不改写正文，也不占用角色卡的 `<background>` 标签。
- 多人卡按角色卡隔离；只自动追踪已出场且有设定的人，以及用户明确指定的人。锁定只保留状态，不冻结行为。
- 记忆增强插件只读参考，默认不写回；旧格式插件自身可能存在迁移副作用，不能承诺绝对零写入。
- 主 API 使用 `generateRaw`，不使用 `generateQuietPrompt`。

插件不做完整地图、坐标、路线或旅行时间计算，不把后台提案当正史，不保证主模型一定采纳提示。完整 beta.7 自动版保留在 `legacy/beta7-auto/` 与历史标签中；旧设置键保持兼容。

### 第一次使用

打开一张带世界观或人物设定的角色卡，直接开始聊天即可。不必先把所有人都确认完。

默认就是同步世界模式，自动结算是开着的，默认每 1 条回复结算一轮。结算发生在正文结束后，新结果最早在下一轮注入。正文没写经过时间，时钟不会推进。

插件只会自动追踪已经出场、并且有设定资料的人，以及你明确指定要追踪的人。

### 界面

扩展设置里能看到「NPC Life · 打开名册与结算面板」和齿轮「设置」，点它们会打开浮动面板。下面的「NPC Life 同步世界」抽屉里是名册、地点和身份管理。

抽屉里的名册卡片，在宽度足够时：左侧是勾选（追踪生活、确认角色、锁定状态、闭关/活动锁、背景状态），右侧是地点和状态输入。

浮动面板在宽度足够时，卡片左右两列排列，内容包括：已追踪名册、资料中的其他名字、近期结算结果、活动与痕迹资料库，以及基本设置。基本设置在宽度足够时，勾选在左、输入框在右；「保存设置」「暂停结算」「导出备份」「导入备份」这些按钮横排。改完设置后要点「保存设置」。

### 把人物标成组织，再改回来

在抽屉的「NPC 名册与动态状态」里，待确认的称呼会出现两个分开的按钮：「确认为人物」和「标为组织」，不会叠在一起。也可以点「手动添加人物」来补人。

标成组织后，这条会出现在组织列表里，并带有「改回人物」按钮。点它可以改回人物：该条会从组织目录里去掉，变成已追踪、已确认的人物。

### 可选设置

浮动面板的「基本设置」里可以开关自动结算、改结算间隔、填写你的称呼，以及打开控制台调试日志。还有一项「启用后台侧写」，默认关闭，只留在面板里，不会写入正史。

「高级设置（下载即可用，一般不用改）」是折叠起来的，里面是动态世界书的条数/轮数上限，以及偶遇概率和地点权重。地点只影响权重，不排除异地，也不计算地图或路线。

### 记忆插件（可选）

默认不读取记忆增强插件。若要参考表格资料，勾选「读取记忆插件（只读参考，非正史，不写回）」后保存。读到的内容只作参考，不能覆盖正史；本插件不会往记忆插件里写回。若记忆插件使用旧数据格式，它自己可能在被读取时做迁移保存，不能承诺绝对零写入。

### 背景状态

名册里被追踪的人物会默认勾选「背景状态」，不用每次手动去开；不想写某个人的近况时，取消勾选即可，插件会记住这个选择。

勾选后，插件会按间隔向主模型注入要求：默认每 3 条角色回复写一次近况（可在面板「基本设置」里改「背景近况间隔」）。到了生成轮次，主模型必须在回复末尾输出专用标签 `<npc_life_background>`，每个人先写一行行为状态词（例如「调查中」），下面再跟一两句到三句情节式短描述，写成短小的一段，篇幅接近角色卡正文底下那种简短背景，但不使用角色卡的 `<background>` 标签，也不写成地点标题或坐标。只要名单非空，就不能因为还没有行为槽就整段省略。如果这些人之前已经生成过近况，插件会把上次的内容一并注入，要求主模型接着写，而不是每轮从头另起一段。

不是生成轮次时，不会向主模型注入这段近况要求，以节省 token；最新一条角色回复底下仍会显示上一轮已经生成过的折叠块。这块「背景状态」默认折叠，点开才看，不会当成正文剧情，也不会写回聊天存档。标签缺失或格式不对时会静默跳过，不污染正文。角色卡里已有的 `<background>` 背景剧情不会被这个功能改掉或盖住。

## 测试

仓库历史中的测试覆盖的是根目录这套 3.3.x 扩展，使用合成数据与 mock，不调用真实付费 API。3.5.x 是酒馆助手脚本，不沿用这套第三方扩展的加载方式。3.5.4 的隔离和别名可以用下面这条检查，它不调用真实接口：

```sh
node --test tests/isolation.test.mjs tests/aliases.test.mjs
```
