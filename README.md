# NPC Life 自动精简版

版本：`3.0.0-beta.7`

目标环境：SillyTavern `1.17.0`

作者：木子 （使用了gpt6.1 sol做的）

一个开关，让有限的NPC短期打算在正常聊天中接续下去。后台参考正文、设定和上次状态，在相关场景给下一轮正文提供连续性参考。仍是测试版，不是完整自主世界模拟，也不保证主模型采纳提示。

## 安装

酒馆扩展安装地址不变：

```text
https://github.com/muzi9277/npc-life
```

已安装者在扩展管理中更新，然后 `Ctrl+F5`。运行文件只有 `index.js`、`manifest.json`、`style.css`，放在 `public/scripts/extensions/third-party/npc-life/`。无后端、无构建、无运行依赖；旧目录剩下但未被导入的JS不会自行执行。

## 开始使用

1. 打开一个角色聊天，在扩展设置开启 **NPC 自动生活**。默认关闭，暂不支持群聊。
2. 默认从角色卡内嵌世界书的明确人物条目保守识别人物，不把所有世界书keys当人。未识别到时，在“高级与恢复”填写一个明确姓名，手工指定会优先使用该人物。
3. 新聊天默认每2条正常AI回复检查，且距上次尝试至少1分钟。升级旧聊天保留原最短间隔，例如10分钟；可在高级区调整。
4. 每批最多一个当前主API请求，更新最多2个人物。计数达到但仍冷却时保留计数，时间到点不会自行发请求，需等下一条新回复。
5. 下一次主生成前，按最新正文场景重建提示。它不会改写已生成正文，也不会向主聊天追加后台消息。

开关下显示等待/冷却/更新/暂停状态，最近三条后台提案在高级区阅读。失败后暂停本聊天，点“恢复”仅解除暂停并重新计数，不立即重试扣费。关闭立即清注入但保留历史。不要同时开启另一份完整版或旧自动版。

## 比beta.6增加了什么

- 从随机自由短札记改为有依据的结构化状态：当前处境、地点/限制原文、私下目标、下一步打算、有限行动类型。新正文可以改变后续打算，准备不会自动升级为已经完成。
- 自动候选最多24个，聊天保留最多12人物，每批最多2人。不自动合并别名，不保证所有卡片的命名格式都能识别；宁可要求手工指定，也不靠关系称呼猜人物。
- 模型必须提供真实消息编号和包含人物姓名的原文引句；未知ID、重复人物、伪造引用、不完整JSON、不安全模板或过长字段整批拒收。文本匹配不能完全证明时态与身份语义正确，仍可能误判。
- 私下目标、心理、后台自由叙述只存后台，不直接进入主正文提示。主提示只选相关人物已公开的原文事实，以及同场时可选的中性准备、求助或重新考虑方向；这些是创作机会，不是已经发生的结果。
- 提示以最新正文为准，命令处理和新用户消息后重新构建；没提及相关人物就不强行插入。关闭、切聊天、开始主生成或改动来源使旧请求失效。
- 不计算剧情日期，日志day固定1；不结算跨地旅行、物品取得、资源数值、关系数值或重大事件，没有NPC相遇判定、召唤、地图、副API和记忆插件联动。

## 连续性、撤销和存储

数据仍在 `extensionSettings['npc-life-auto']`，按角色卡与聊天隔离。新版存于每聊天的 `v7` 字段，旧beta.6日志保留但不继续注入，不自动转为已核实人物状态；完整版 `extensionSettings['npc-life']` 完全不改。

消息只持久化紧凑来源摘要，不在每条记录重复复制全聊天。最多保留12次事务快照和20条后台提案；编辑、删除、重抽会撤销首个受影响提交及后继并恢复对应人物状态。超出保留窗口的早期正文或世界书发生变化，会清掉本聊天后台推演、建立当前基线，保留用户正文和现实限频时间，不自动付费重建。

新版单聊天约256KiB、模块总存档约8MiB上限，按保守UTF-16文本大小估算。超限拒绝提交并暂停，不偷偷删除别的聊天。旧版自由日志仍保留，可能占用容量，可先导出备份再整理。

高级区可导出/导入本模块JSON，或确认后重建本聊天后台。导入先校验并默认关闭，正文来源不匹配的推演不会激活。备份含人物短记录、原文短引句和旧版数据，可能包含剧情隐私，请自行保管；插件不读取或导出连接密钥。宿主防抖保存不等于防断电数据库事务。

## 请求、费用和预算

独立调用 `generateRaw`，显式发送最多约6000字符近期正文、每人物最多2400字符检索设定及有限旧状态。资料会发送到当前主API，可能产生费用；不使用 `generateQuietPrompt`，不默认发送完整聊天。

仅支持已核实的聊天补全（`openai`后端）与Text Completion（`textgenerationwebui`后端）。按独有请求标记，在本次载荷事件中设置2400输出token预算，支持 `max_tokens` / `max_completion_tokens` 与文本后端的相应字段，不通过 `responseLength` 修改共享主预设。其他后端明确暂停；供应商是否遵守预算、推理模型是否需要更多预算仍待实测，不能据此宣称20字截断根因已修复。

全局最多一个后台在途请求；120秒超时作废结果并暂停，但宿主 `generateRaw` 没有可用的独立取消参数，所以保持单飞锁直到原请求结束，不启动第二个悬挂请求，不广播全局停止干扰玩家。已发请求不保证免计费。其他扩展仍可能修改请求；模板清洗和资料提示不能提供任意第三方扩展的完全隔离。
